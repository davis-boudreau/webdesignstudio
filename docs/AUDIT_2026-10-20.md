# Follow-up project audit

20 October 2026, America/Halifax.

Reviewed the current local project after the eight-step wizard and teaching
workspace changes. This follows the 19 October audit; its results remain
historical. The working tree contains the accumulated, uncommitted feature work.
User snapshots `test.html` and `tokens.css` were not modified.

## Scope and findings

Reviewed startup disclosures, preview lifecycle, wizard/control routing, token
generation, typography/spacing demonstrations, semantic editing, import/storage
validation, generated markup, font loading, accessibility preferences and the
existing CI/Pages workflows. Repeated functional browser checks and live-font
checks in isolated profiles. This is a targeted code and functional audit, not a
penetration test or accessibility certification.

| Finding | Effect | Correction |
| --- | --- | --- |
| Spacing lesson and CSS used different step lists | The lesson displayed `space-3`, which was not exported, and omitted exported steps | Share `SPACING_STEPS` between chart and CSS generation; labels update from the same unit; bars remain constrained to the available width |
| Type ladder fixed its line-height at 1.2 | Wizard leading changes were absent from the teaching ladder | Use heading and body line-height according to each row's font role |
| Heading specimens fixed their weight at 700; ladder inherited body weight | The lesson could disagree with the configured heading emphasis | Use the existing heading-weight custom property with a safe 700 fallback; retain body weight 400 |
| Section scroll offset was fixed at 125px | Wrapped mobile headers could cover the section heading after navigation | Measure sticky header/navigation heights and update the section scroll-margin on resize |

The initial repeated suite passed 474 checks after the requested startup change.
Three new checks passed for editing a collapsed preview and opening it without
losing its document, dimensions or current CSS. Focused browser probes and source
inspection confirmed the teaching mismatches before correction. Regression checks
cover exported/chart agreement, line-height/weight, spacing-unit edits and section
heading visibility at 320, 390 and 1440px.

## Requested startup behaviour

This audit records the Colour systems default requested at that time. The user's
subsequent preference restores **1. Responsive page preview** as the only expanded
section. README and `docs/PROGRESS.md` describe the current default.

Only **3. Colour systems** is expanded on a normal load. All other centre sections
and wizard disclosures start collapsed. The responsive preview retains Fluid
configuration and receives live updates while closed. First opening refreshes its
dimensions. User toggles, expand/collapse all, lesson shortcuts and explicit URL
fragment destinations retain their existing navigation behaviour.

The optional accessibility/font fixtures now explicitly reveal the preview they
test rather than relying on a particular startup accordion being open.

## Remaining findings and limits

1. **CI validation gap:** CI still runs only the structure check. Pages deployment
   is a separate workflow and is not gated on browser tests. The workflows were
   inspected but not changed or executed in this audit.
2. **Architecture debt:** modules still wrap shared global functions, and the
   learning module moves existing controls after initialization. This preserves
   current bindings but makes ordering important. Coverage checks reduce risk;
   migration to explicit shared-state/module APIs remains separate work.
3. **Manual/browser coverage:** Firefox, Safari, screen-reader navigation,
   interactive zoom and real pointer/touch review remain outstanding. Headless
   Chrome checks do not establish complete accessibility or every possible
   rendered colour combination.
4. Download checks verify routed filenames/content, not operating-system download
   completion. Clipboard rejection is covered; interactive clipboard permission
   success still needs manual testing.

No commits, pushes, publishing or deployment were performed.
